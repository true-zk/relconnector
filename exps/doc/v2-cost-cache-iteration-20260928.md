# v2 缓存策略迭代与固定工作集实验

## 目标与判定

目标是在十个数据集上避免缓存造成的明显回退，并保留高复用或高编码成本负载的加速。不能把“有缓存命中”直接当作成功，也不能在只有一次试跑时宣称所有数据集均不劣化。

第一轮使用同一套通用策略，没有按数据集名称开关缓存。逐数据集比较全关基线，报告最差回退、总时间、后续 epoch 时间和累计回本轮次。首轮为筛选，后续应对正负结果做至少三次配对重复，并给出波动范围；不能把一个预设的 3% 容忍度当作严格“不劣化”的证明。

## 候选算法：`cache_strategy=cost`

旧实现仍是默认 `legacy`，新策略显式启用。当前是待测候选，尚未作为默认训练策略推广。

### 内存文本缓存

- 从共享查找／保留槽切换为每个 worker 的有界本地 LRU，减少共享锁、RPC 和满载后继续探测的成本。
- 每个文本列独立累计收益。命中收益用该向量历史编码时间估算，成本实测查找、复制、拼接、准入与淘汰耗时。
- 16 次探测后，如果估计节省不足维护成本的 1.25 倍，旁路 64 次调用，然后重探测；epoch 边界允许重新探测。
- 容量估算同时计算向量、字符串及元数据，入缓存的向量拥有独立存储，不会因为保留小切片而钉住整个大张量。
- 这是成本估计控制器，平均行编码成本可能不能准确代表长短文本差异，必须用实际端到端结果检验。

### 磁盘文本缓存

- 将一组有序文本的完整向量存为不可变内容寻址块，通过临时文件与原子替换发布。不同 worker 可读取同一块，不经过中央 SQLite 写事务、reservation 或 checkpoint。
- 键使用原始完整文本块，不受本轮 RAM 命中后剩余文本子集影响；模型、数据库版本及执行模式由原有命名空间隔离。
- 新写入使用已观察模型编码时间的 3% 作为预算，同时要求估计编码成本足够覆盖预估写成本。该预算允许一次写入超支，且不等于端到端 3% 的硬上界。
- 最后一个 epoch 不再建设新缓存。每个 worker 的新增写入有字节预算，磁盘空间不足时拒绝发布。
- 查找连续亏损后旁路；慢读或 I/O 故障也会退避。缺失、截断或格式不匹配时回退到模型编码。
- 磁盘命中直接返回向量块，避免读回后再逐行复制填充 RAM。

**重要限制：块内文本的顺序或分组变化会使磁盘键改变。因此固定回放只验证可重复输入上的跨 epoch 收益，不能独立证明自然重采样上的收益。实验另外运行自然采样对照。** 后续若自然采样仍有很多昂贵重复文本但块级命中很低，再评估批量行索引方案，不能只根据固定回放结果选择算法。

### 普通特征缓存

第一版 `cost` 保守关闭 raw 与 encoded 缓存，避免低命中块缓存维护和跨进程 Manager 查找。没有宣称普通特征缓存普遍无效；已有 Arxiv 等结果提示它可能有明显收益。本轮必须同时保留旧策略作为参照，若高重复负载因关闭 encoded 而损失收益，再加入按表成本控制的 encoded 缓存。

`off` 同时关闭 raw、encoded 和文本跨调用复用，但保留窗口内去重、向量化与流水线。还为完全关闭文本缓存的路径移除了无意义的逐行向量拆装，使新策略面对的是直接编码基线。

## 固定 100 batches 的实验协议

1. 每个数据集准备最多 100 个真实训练 batches。若训练集本身不足，则按实际数量记录，不人工重复凑数。
2. 固定 seed 节点、时间、标签、邻居子图、边与推荐任务的正负样本；每个文件及清单都有 SHA-256 校验。
3. 五个 epoch 都加载同一组输入，仅更新 epoch 标识；保持真实 SQL 特征获取、文本编码、组装和模型训练。
4. 准备固定输入的时间单独记录。正式每组使用新的模型、四个 worker、相同严格训练顺序及关闭跨 epoch 预取。
5. schema/topology 初始化缓存先由准备阶段预热，各组文本缓存均从空目录开始。在同一次训练的五轮中保持缓存，组间删除本实验自己的派生文本缓存。
6. 变体顺序用固定随机种子打乱。保留源代码快照、参数、输入指纹、原始日志、逐轮计时和 worker 遥测。

| 组 | raw / encoded | 新 RAM | 新 disk | 用途 |
|---|---|---|---|---|
| off | 关 | 关 | 关 | 直接编码基线 |
| legacy | 原配置 | 旧文本策略 | 旧文本策略 | 旧实现参照 |
| cost_ram | 关 | 开 | 关 | 内存净贡献 |
| cost_disk_only | 关 | 关 | 开 | 磁盘跨 epoch 净贡献 |
| cost_disk | 关 | 开 | 开 | 两级组合及交互 |

另对所有十个数据集运行 `off` / `cost_disk`，使用正常跨 epoch 重采样、ready 消费和跨 epoch 预取，2 epochs × 最多 50 batches。该部分用于检验实际训练流程中不断变化的工作负载是否回退。两类实验都保持四个 worker；仅在同一输入与调度协议内对照，不将两类实验的绝对耗时直接混比。

## 指标与归因

- `end_to_end_s`：整个 benchmark，包括初始化、缓存管理器建立和退出。
- `pipeline_s`：进程流水线生命周期，包括末尾诊断收集。
- `training_wall_s`：各 epoch 的完整墙钟时间之和，包含首批等待；冷轮包含流水线子进程启动。
- `cold_epoch_s` 与后四轮均值：区分建设成本和复用收益。
- 累计回本轮次：与全关基线对比，累计耗时首次领先且后续观测轮次始终领先的位置。
- 每轮模型编码条数/时间、RAM 与 disk 命中、磁盘写入量、实际读写耗时、旁路次数、估计节省时间。

worker 累计操作耗时不是端到端墙钟分解；估计节省时间也不是实测反事实。不能把并行 worker 的秒数简单相加后直接解释端到端收益。

OS 页缓存未清空，文件系统位置保持一致。所谓磁盘命中可能由 OS 页缓存提供，此实验测量的是应用持久缓存的实际部署表现，不能称为冷机械盘读速实验。尚未记录进程树总 RSS，父进程 RSS 不能代表内存总开销。

## 同时修正的实验问题

原运行时的 `cross_epoch_prefetch=False` 没有阻止 seed 生产线程提前进入下一轮。现已用训练完成信号控制 epoch 放行，并覆盖普通与空 epoch 的测试。旧 `duration_s` 从首个已就绪 batch 开始，遗漏首批等待；保留该字段兼容，新增 `wall_duration_s` 和 `first_batch_wait_s` 用于本轮分析。

## 已完成的验证

- 最终完整测试集 82 项通过；修改模块的 Ruff 检查通过，Pyright 为 0 errors。日志位于 `benchmarks/cache-iteration-smoke/verified-tests.log`。
- 缓存单元与集成测试覆盖收益探测/旁路、顺序恢复、重复展开、跨 epoch 计数、容量淘汰、磁盘跨实例命中、原子并发写入、损坏回退和末轮停止写入。
- 固定输入测试确认跨 epoch 标签、边与负样本一致，并拒绝身份或文件校验不匹配。
- 真实 F1 小样本功能矩阵完成：4 个固定回放组各 3 × 4 batches，加 2 个自然采样组各 2 × 4 batches，无失败；固定回放指纹一致，平均 loss 的最大差约 8.6e-7。
- 该小样本在旧实验尚未结束时运行，仅用于功能与数值一致性检查，不作为缓存性能结论。

## 运行入口

```bash
PYTHONPATH=relconnector_v2 ../.venv/bin/python -m relconnector_v2.run_cache_iteration \
  --output-dir benchmarks/cache-iteration-100x5-v2 \
  --max-batches 100 --epochs 5 --natural-check --device cuda:0
```

可用 `--wait-for-pid PID` 等待已有实验释放资源，再开始测量。支持 `--datasets`、`--profiles` 和 `--repeats`，输出 `status.json`、`REPORT.md`、`summary.json/csv`。正式运行使用冻结源码，不受后续工作区编辑影响。

当前正式筛选目录为 `benchmarks/cache-iteration-100x5-v2`，已提交后台顺序执行：十个数据集 × 五个固定输入变体，加十个数据集 × 两个自然采样变体，共 70 个训练配置，各一次。等待旧消融矩阵 PID 97515 结束后启动；实际状态以该目录 `status.json` 为准。更早的 v1 队列在执行任何测量前已撤下，其状态文件保留原因。

单独准备或使用回放输入的参数为 `benchmark --replay-dir PATH --prepare-replay-only` 和 `benchmark --replay-dir PATH`；数据库、任务、seed、batch size、fanout 等身份必须匹配，否则拒绝复用。
