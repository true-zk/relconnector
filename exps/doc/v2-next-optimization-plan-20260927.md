## 第二轮：共享缓存投影与特征复制（2026-09-27）

本轮 A 是已经包含上一轮专用行选择的当前 v2；源码保存于
`benchmarks/v2-cache-projection-20260927/baseline/relconnector_v2`。
不得将本轮增量与上轮原始基线混用。

### 假设与本轮实现

共享缓存命中多个块时，现有流程是“每块取行 → 拼接 → 跨进程返回 → 再次取行 → 与未命中行合并/恢复顺序 → 按采样节点展开”。缓存命中避免编码，但这些内存操作仍存在。

1. **合并取行与拼接**：对 CPU 稠密列、定宽向量一次分配最终结果，各缓存块直接写入相应连续区间。避免先为所有块构造中间结果再复制到拼接结果。变长列、需要梯度的输入等保留原路径。
2. **复用已经紧凑的命中结果**：只有缓存返回的行数及行号严格证明是完整顺序时才跳过第二次取行；请求位置可以不连续，之后仍按请求顺序恢复。缓存块前缀、乱序行不能误用此路径。
3. 不改变缓存预算、准入策略、邻居采样、时间约束或特征值。

### 验证与判定

- 精确比对多块、重复行、空块、非连续源张量、缺失值、标签、字典、变长列和部分命中/乱序恢复；覆盖梯度回退和缓存发布安全。
- 微实验交错测量 2/8/32 个缓存块、窄列和 300 维列，确认数据搬运收益以及小输入开销。
- 正确性测试结束后，Salt 使用相同 GPU、固定 4 worker、严格顺序、共享编码缓存 2 GiB、文本缓存 512 MiB，关闭磁盘文本缓存；2 epoch × 30 batch。执行 A→B→B→A，独立进程缓存，初始化缓存热启动。
- 短时实验只用于筛选。若墙钟结果不稳定或回退，不以微实验替代端到端结论；进一步拆分消融，或撤回候选。

### 决策模型（待实现，避免只按数据集名选择）

对某张表的一次请求，记命中行数为 `H`，每行编码后字节数为 `b`，命中缓存块数为 `K`，单行重新读取并编码的平均成本为 `c_e`。共享缓存的净收益可估为：

`G = H × c_e − (L_rpc + T_index + T_projection(H, b, K) + T_restore)`。

只有 `G > 0` 才值得保留该共享路径；估计应来自滑动窗口，而非一次请求。还需把缓存引入的额外驻留内存纳入预算。`T_projection` 不是磁盘 I/O，也不能用命中率替代：高命中率仍可能对应大量复制。对稠密多块数据，本轮融合将“各块输出合计约 H×b 字节 + 最终拼接约 H×b 字节”的两组输出缓冲，减少为一组最终输出；这不等于整个进程 RSS 减半，RPC、源缓存及其他阶段仍占内存。

读取策略可以比较 `C_sparse = q_s×L + B_s/β` 与 `C_block = q_b×L + B_b/β`，其中 `q` 为查询次数，`L` 为固定查询开销，`B` 为实际返回字节，`β` 为实测有效读取吞吐。块读取可能减少查询次数却增大读取字节，应该根据工作负载校准，而非只比较请求行占比。

### 文本特征转换的下一项局部候选

上一轮 Salt 的 `salt-b4` 中，salesdocumentitem 的 `frame_convert` 为 71.06 工作进程秒，其中 `map_text_embedded` 为 59.81 秒；全局 `text_expand` 为 10.41 秒、`text_model` 为 8.55 秒。这些计时嵌套，不能相加，但说明剩余转换开销不仅是文本模型推理。当前 `features/text.py` 两处用 `stack(唯一文本向量)[inverse]` 恢复行序，可进一步对比 `index_select`、批量共享缓存取向量以及减少逐条 Python 对象创建。需覆盖重复文本、空串、缺失值、缓存等待/失败、逐元素等价；不能通过改变文本归一化或向量精度换取系统加速。本轮不把这一候选混入共享编码缓存实验。

### 用关键路径决定下一轮优先级

在各阶段充分重叠的稳态近似下，每批吞吐时间可写作
`T_batch ≈ max(T_sample, T_assemble / p_eff, T_gpu) + T_bubble`。
`p_eff` 是考虑共享 CPU、数据库、内存带宽和通信竞争后的有效并行度，不能直接用 worker 数替代；`T_bubble` 包含队列断供和严格顺序引起的等待。这个近似用于诊断，不代替实际墙钟测量。某项累计 worker 时间下降，不一定缩短关键路径；需要同时看流水线、就绪等待及完整工作量。外部 CPU 作业会改变 `p_eff`，因此必须记录并发负载，繁忙主机上的少量对照只作探索结果。
