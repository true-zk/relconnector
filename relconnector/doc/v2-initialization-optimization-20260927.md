# v2 初始化启发式优化（2026-09-27）

## 问题与实现

Event 空初始化缓存实测耗时 2164.00 秒，其中 schema 1895.62 秒、拓扑 267.95 秒。events 表实际参与统计的 95 个数值列合计约 1745 秒；原路径逐列扫描计算均值/标准差，再逐列 SQL 排序、Python 逐值遍历求分位数。

在 `relconnector_v2/features/schema.py` 实现通用的内存预算启发式，无数据集名称判断：

- 对含数值特征的表，按相同时间截断条件计数；单列按每行 float64 的 8 字节估算缓冲。
- 数值缓冲预算默认 128 MiB，每组列数为 min(32, floor(预算 / 单列大小))。分组投影读取，避免每列单独扫描；SQL/解码批次最多 8192 行。
- 能放入预算的列保留全量有限数值，计算均值、标准差，并通过 NumPy 原地 partition 选择精确分位点，沿用线性插值；不抽样，不近似分位数。方差临时数组按 8192 元素分块。
- 单列超过预算时保留原流式统计与 SQL 排序路径，分位点提取改为 NumPy 批量过滤和索引；时间统计也改为分块索引，避免逐值 Python 遍历。
- 预算为数值缓冲上限，不是整个进程 RSS 上限；SQL/DataFrame 分块、解释器、模型和图仍有自身内存。builder 的 numerical_buffer_bytes 参数可调整，设为 0 可禁用分组路径。
- Schema 缓存算法版本改为 v2，预算参与缓存键，旧 schema 首次需要重新生成。图拓扑缓存格式和构建逻辑未改动，已有拓扑缓存可继续复用。

## Event 完整冷初始化复测

优化前后都使用各自独立空缓存目录，仅调用 prepare，不训练，不清除操作系统文件缓存，Python 导入不计时，包含缓存保存。确认 schema/topology 均为 cache_hit=false。

| 阶段 | 优化前（秒） | 优化后（秒） |
| --- | ---: | ---: |
| Schema | 1895.62 | 335.66 |
| 拓扑 | 267.95 | 269.92 |
| 其他准备 | 0.43 | 0.42 |
| 总初始化 | 2164.00 | 606.01 |

总初始化从 36 分 4 秒降到 10 分 6 秒，耗时减少 72.00%，加速 3.571×；schema 约加速 5.647×。拓扑没有优化，耗时基本持平。这是同机单次前后对照，不是多次重复实验；文件缓存与运行负载仍可能影响绝对值。

## 正确性和兼容性

- Event 新旧 schema 的 329 项统计逐项比较：类别和时间统计完全相同，数值分位数完全相同；均值/标准差最大绝对差 7.958e-13，通过 rtol=atol=1e-12，差异来自浮点求和顺序。
- 新增 5 项测试：有限值和缺失/非法值、分组与流式一致性、预算不足回退、空表/单值、时间截断和分块边界、隐藏列、缓存往返、大偏移量方差。
- v2 全套 59 项单元/进程测试通过；Ruff 与改动文件 diff 检查通过。
- Event 使用新生成 schema 完整训练两轮，各 38 batch，共 76 batch / 38478 样本，用时 38.77 秒，有限损失，四个 worker 诊断及组装数完整。该时间复用刚生成的初始化缓存，不与冷初始化相加作为一次端到端实测。
- 小数据集 F1 使用独立空缓存目录，完整训练两轮，各 6 batch，共 12 batch，用时 28.11 秒，有限损失，四个 worker 诊断完整。用于兼容性验证，不宣称小数据集性能提升。
- 未重跑其他八个数据集，未做训练损失严格数值等价验收。

## 剩余工作

优化后拓扑占初始化约 44.5%，可进一步分析重复关系扫描/排序和邻接数组构建。数值分组扫描仍有读取和解码开销；分类统计仍走原路径。此次不改变图结构和邻居顺序，避免将多个正确性敏感改动叠加。
