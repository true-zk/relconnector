# v2 十任务 GPU benchmark（实验 20260925，已完成）

**最终状态（2026-09-27 03:25）：10/10 完成，共 76,186 batch。** 成功运行耗时合计 46,242.51 秒，按相同各任务批次数折算比历史 v1 加速 1.703×（耗时减少 41.28%）。Event、Trial 仍回退；冷热缓存、实现版本和 Amazon 缺失统计等限制见[最终完整报告](v2-full-matrix-20260925-final.md)。下文保留过程记录，其中“当前”“待完成”按对应历史时间理解。

## 口径

- 十个任务取自 `relconnector_v2.run_validation_matrix.CASES`。
- 每项 2 epoch、每 epoch 最多 10,000 batch、batch size 512、fanout 128×128、channels 128、CUDA、4 个组装进程、初始 1 个进程、adaptive 磁盘文本 embedding 缓存。
- 当前机器为 RTX 4090；历史 batch/vanilla/v1 数据取自 `doc/gpu-feature-optimization-experiment.md`，其配置为 1 epoch。比较使用端到端秒数除以实际完成 batch 数；此指标会摊薄 v2 的一次性启动和缓存构建成本，不能当作同条件因果加速比。
- Ratebeer 每轮只取 10,000 batch，历史完整轮次为 20,743 batch；对比按秒/batch 计算。历史 v1 在 14,400 秒时只完成 15,686 batch，其比较值仅为观测吞吐近似。
- v2 文本缓存启动状态不一致：Arxiv 在本轮前已有磁盘 embedding；Stack 续跑复用前次运行和诊断留下的磁盘 embedding，其他任务需逐项检查；逐项诊断会保留实际启用情况。初始化 schema/topology 缓存是否命中，也会影响端到端对比。
- `doc/bottleneck-analysis-and-optimization.md` 的历史遥测显示 HM/Salt 的文本缓存命中率为 99.23%/99.95%，而 Amazon/Stack 为 23.44%/34.62%；这为自适应磁盘策略的启停提供了独立参照。

结果原始文件：`benchmarks/v2-full-matrix-20260925/v2.jsonl`；运行日志：`benchmarks/v2-full-matrix-20260925/run.log`；复算脚本：`benchmarks/v2-full-matrix-20260925/compare.py`。

比值大于 1 表示 v2 的观测秒/batch 更低。Trial 的第二轮没有重复进行文本模型编码，但 v2 端到端平均吞吐仍低于历史 v1；两者不能混同。F1 数据库约 6 MiB，未达到磁盘缓存的大库门槛，按预期关闭。

Event 的 2194.0 s 中，2166.5 s 是首次 schema/topology 初始化，流水线双轮训练只占 27.4 s。其 `events` 表有 96 个数值列；v2 首次计算各列统计与分位数时反复扫描数据库。该任务不需要磁盘 embedding，第二轮模型编码数为 0。

Arxiv 本轮命中既有磁盘缓存（起始约 533,065 条），双轮完成 2,088 batch。磁盘读取命中 939,742 条，并补写 186,040 条；第一轮新编码 184,724 条，第二轮只编码 1,316 条，比第一轮减少约 99.3%。其两轮 epoch 训练分别为 491.9 s 和 283.3 s。对历史 v1 的 5.82× 是按每 batch 端到端耗时换算的跨实验比值，不是同环境配对测量。

HM 的文本缓存命中率高，模型编码仅占原两轮流水线的很小一部分，因此自适应策略没有启用磁盘 embedding。原共享编码缓存跨进程传输完整 chunk，导致缓存命中仍然产生大量开销；修复后改为局部缓存并只传输所需行。完整复测两轮流水线从 4603.0 s 降至 1756.3 s；具体诊断见 `doc/v2-hm-regression-20260925.md`。原矩阵结果保留在原始 JSONL，比较脚本采用追加的修复后记录。

Avito 两轮各 4,322 batch，训练分别用时 800.3/780.1 s，平均损失从 0.03386 降至 0.03275。共享编码缓存命中率约 93.3%，第二轮没有文本模型编码；四个 worker 的模型编码总时间约 5.1 s，因而关闭磁盘 embedding 符合自适应策略。v2 比历史 v1 按秒/batch 快约 1.49 倍，但比历史 batch 版本慢约 6%；主要耗时不在重复文本编码，两轮流水线总等待就绪 batch 约 544.8 s。

Salt 修复前两轮流水线用时 18194.9 s，其中等待就绪 batch 16405.1 s（约 90%）；第二轮文本模型编码 0 条，磁盘 embedding 关闭符合高命中率的选择，但整体吞吐比历史 v1 慢约 3.2 倍。共享文本缓存命中率约 99.93%，而每个组装 worker 都执行约 62.4 万次共享文本缓存查询；单个 worker 的查询累计约 7,633 s。该次瓶颈在高频缓存访问和组装，不在重复模型编码。

Salt 的纯本地文本缓存曾在 2×50 batch 诊断短测中从 498.4 s 降至 141.8 s。现已改为各任务统一的自适应策略：运行时自动启停 worker 的共享向量位置索引，保留跨进程编码协调。自适应最终短测为 153.4 s，模型编码数与原共享模式完全相同；已移除按 Salt 名称指定本地缓存的规则。2026-09-26 12:35 已完成完整自适应复测：两轮 6,340 batch / 3,245,578 样本，用时 5208.2 秒，较修复前快 3.51×，按秒/batch 较历史 v1 快 1.09×。共享文本查询累计从约 30,532 worker 秒降至 802.5 worker 秒；模型输入仍是 146,635 / 0。上表已更新为完整自适应结果。诊断、实现和短测见 `doc/v2-salt-regression-20260926.md`。
