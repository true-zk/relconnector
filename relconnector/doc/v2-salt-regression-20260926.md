# Salt v2 共享文本缓存退化与修复（2026-09-26）

## 完整运行的瓶颈

`rel-salt/item-incoterms` 使用 4 个组装进程、2 epoch、每轮 3,170 batch。原 v2 运行完成 6,340 batch，用时 18,260.2 s，即 2.880 s/batch；历史 v1 是 2,832.6 s / 3,170 batch，原 v2 单位 batch 慢约 3.2 倍。

流水线用时 18,194.9 s，其中等待就绪 batch 16,405.1 s（约 90%）。共享文本缓存命中率约 99.93%，第二轮文本模型编码为 0；四个 worker 的模型编码计时合计约 32 s。每个 worker 都调用约 62.4 万次共享文本缓存查询，单个 worker 的该项累计约 7,633 s。高频共享缓存查询与组装是主要耗时，磁盘 embedding 缓存不能解决这个退化。

## 修复方式与短测

诊断时增加 `--text-cache-scope local`。原实现启用共享文本缓存时会关闭 worker 本地缓存，导致 Salt 的重复文本每次都要查询跨进程共享表。以下对照用 1,024 MiB 本地总预算验证瓶颈；这是诊断配置，已被下文统一自适应策略取代，不再按 Salt 名称选择本地模式。

在第二张 RTX 4090 上，保持 4 worker、同样采样配置，分别用共享 512 MiB 和本地 1,024 MiB 跑 2 epoch × 50 batch；同时第一张 GPU 在运行 Stack，因此这是同机顺序短测，不是独占机器测量。

| 指标 | 共享 512 MiB | 本地 1,024 MiB |
| --- | ---: | ---: |
| 完成 batch / 样本 | 100 / 51,200 | 100 / 51,200 |
| 端到端时间 | 498.4 s | 141.8 s |
| 流水线时间 | 486.2 s | 129.9 s |
| 等待就绪 batch | 454.8 s | 99.5 s |
| 四 worker 文本缓存查询累计 | 831.5 s | 48.8 s |
| 模型编码 e0 / e1 | 99,085 / 6,809 | 321,030 / 40,521 |
| 平均损失 | 1.1864 | 1.1748 |

短测端到端加速 3.51 倍；额外的本地编码成本低于省下的共享缓存查询成本。两组训练顺序可能不同，损失只用于排除明显异常。短测不能代替完整规模结论。

## 统一自适应策略

默认 `--text-cache-scope adaptive` 对所有数据集使用同一策略，向量仍保持共享，第一次编码仍由共享 reservation 协调。worker 在本地只保存已发布向量的文本到共享槽位索引；已发布槽位在本次运行内不会被覆盖，因此命中后可直接批量读取，无需重新哈希或进入跨进程锁。返回值复制到独立张量，调用方不能修改缓存本体。

每个 worker 至少观察 64 次调用、1,024 次文本请求；窗口共享命中率至少 80%、查询累计至少 5 ms 时启用本地索引。启用后保留两个窗口建立索引；随后若连续两个窗口本地命中率低于 20%，释放索引并冷却至少四个窗口。重复低收益切换会延长冷却，最长 32 个窗口。每个 worker 的索引元数据估算预算为 32 MiB，按 LRU 淘汰；向量不重复缓存。

磁盘缓存仍独立根据数据库大小、内存命中率和编码耗时启用。该策略无需知道数据集名称；Salt/F1/Arxiv 使用相同参数。矩阵通过 `--revalidate-text-cache rel-salt` 指定需要重测的实验结果，此选项只管理断点复测，不改变 Salt 的运行算法。

自适应 Salt 的最终 2×50 batch 短测已完成：端到端 153.4 s、流水线 141.3 s、等待 111.3 s，相比原共享短测端到端快 3.25 倍。四个 worker 文本缓存查询累计计时从 831.5 s 降至 71.2 s。两轮模型编码仍为 99,085 / 6,809，与原共享模式完全相同；第二轮的 6,809 条是本次短测新遇到的文本，不能将其解释为索引导致的重复编码。四个 worker 均自动激活一次索引，合计 4,964,260 次快速命中、约 64.8 MiB 索引元数据，无索引淘汰或退回；磁盘缓存保持关闭。

F1 使用相同参数完成全部 12 batch、27.12 s，对照共享模式为 27.13 s：四个 worker 均未启用本地索引，磁盘缓存也未启用。Salt 完整两轮尚待复测；以上共享、本地和自适应短测均与 Stack 并行运行，不能直接外推最终加速比。

Arxiv 使用相同参数完成 100 batch、303.58 s，对照共享模式为 309.73 s。它复用已有磁盘缓存，读取命中 676,274 条，两轮模型编码 0 / 0。三个 worker 曾短暂启用本地索引，观察到低本地复用后自动关闭并释放；另一个 worker 始终未启用，最终四个 worker 均保持磁盘路径而无本地索引。这验证了运行时回退，也说明磁盘策略与索引策略可以独立工作；本轮不是空磁盘缓存启动实验。仅约 2% 的耗时差不能证明稳定加速。

低复用回退阶段直接使用原共享查询路径，仅增加窗口统计，避免在索引关闭时构造不使用的位置列表。最终代码通过 32 项单元/进程测试以及 Ruff、diff 检查。

原始短测：`benchmarks/salt-cache-scope-20260926/shared.jsonl`、`local.jsonl`、`run.log`。完整矩阵原始数据：`benchmarks/v2-full-matrix-20260925/v2.jsonl`。

自适应最终验证原始数据：同目录的 `adaptive-final-rel-salt.jsonl`、`adaptive-final-rel-f1.jsonl`、`adaptive-final-rel-arxiv.jsonl` 和 `adaptive-final.log`；F1/Arxiv 对照为 `control-rel-f1.jsonl`、`control-rel-arxiv.jsonl`。汇总在 `adaptive-summary.md`，可运行 `summarize_adaptive.py` 复算。初版探测结果保留在 `adaptive-*.jsonl`。


## 完整自适应复测（2026-09-26 12:35 完成）

使用最终共享查询批量化实现及统一 adaptive 策略，2 epoch 共 6,340 batch、
3,245,578 样本，端到端 5208.23 秒，流水线 5196.23 秒，ready 等待 3361.36 秒。
两轮训练时间分别为 2473.30/2676.67 秒；模型输入 146,635/0，磁盘文本缓存关闭。
每个 worker 的位置索引均启用一次且未退出/淘汰，元数据各约 28.7 MiB。
共享文本查询累计 802.46 worker 秒；剩余主要耗时包括 frame_gather 4086.25、
encoded_cache_lookup 3033.44、encoded_cache_put 1682.53 worker 秒。
这些 worker 耗时有并行与嵌套，不能直接相加解释端到端时间。

相对修复前同规模 v2 的 18260.23 秒，端到端约快 3.51×。模型输入数不变，
改善并非通过减少训练 batch 或重复模型编码口径取得。
当前平均 0.82149 秒/batch，历史 v1 为 2832.6/3170 = 0.89356 秒/batch，
跨实验观察加速约 1.088×（耗时减少约 8.1%）。初始化缓存及历史机器负载等差异仍适用，
不能把短测的 3.25× 或完整相对旧 v2 的 3.51× 当成对 v1 的提升。
